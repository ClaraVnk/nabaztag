# A WPA3-only access point that will only do hash-to-element.
#
# hostapd's sae_pwe=1, and the one setting UniFi Network 10.x does not show.
# On 2026-11-07 Nabazprout, hunting and pecking, went orange on a WPA3-only
# UniFi SSID and joined the same SSID in transition mode; this scenario was
# written that night as the reproduction, and it asserted the failure.
#
# What such an AP does with a hunted-and-pecked commit is not refuse it.
# hostapd's handle_auth_sae() checks sae_status_success() -- status 0 does
# not fit sae_pwe=1 -- and goes to remove_sta without a reply. The station
# sees nothing, times out in AUTH, and the bytecode starts over. The first
# version of this AP answered status 1 instead; the silence is the faithful
# model, and it is what the firmware before wpa3_h2e gets here: AUTH for
# ever.
#
# With wpa3_h2e the station reads bit 5 of the RSNXE in the beacon, derives
# PT (12.4.4.2.3) and a PWE from it, sends its commit with status 126, puts
# the RSNXE in its association request and repeats it in message 2. The AP
# derives PT and PWE from its own reading of the standard (src/vaph2e.c),
# checks the station library agrees, and both halves are checked against
# RFC 9380 and Annex J.10 before the run starts.
#
# Expected outcome: RUN, and the AP saw hash-to-element.

ap 02:00:5e:10:00:01 Terrier 6 wpa3-sae -52 h2e-only
psk nabaztag
conf obj/conf/wpa3.eeprom
tick 50
stop 30000

at 20000 expect RUN
at 20000 expect-sae h2e
